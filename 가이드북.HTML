4. Step 1 — Flask 앱 구조 & SQLite 연동

Step 1 입문

Flask 앱이란?

Flask는 Python으로 웹 서버를 만들게 해주는 마이크로 프레임워크입니다. "마이크로"는 기능이 적다는 뜻이 아니라, 필요한 것만 골라 쓰라는 철학입니다.

# app.py 핵심 구조
from flask import Flask

app = Flask(__name__)          # 1. 앱 인스턴스 생성

@app.route("/")                # 2. URL 경로 연결 (라우팅)
def index():
    return redirect(url_for("posts_list"))

if __name__ == "__main__":
    app.run(debug=True)         # 3. 개발 서버 실행
Step 1 입문

SQLite 연결 관리

이 프로젝트는 요청 단위 연결 패턴을 사용합니다. 매 요청마다 DB 연결을 만들고, 요청이 끝나면 닫습니다.

def get_db():
    """요청 내에서 DB 연결을 재사용합니다."""
    if "db" not in g:                              # g: 요청 단위 저장소
        DB_PATH.parent.mkdir(parents=True, exist_ok=True)
        g.db = sqlite3.connect(DB_PATH)            # 연결 생성
        g.db.row_factory = sqlite3.Row             # 결과를 dict처럼 사용
    return g.db

@app.teardown_appcontext
def close_db(_error):
    """요청이 끝나면 연결을 자동으로 닫습니다."""
    db = g.pop("db", None)
    if db is not None:
        db.close()

중급 왜 g 객체를 사용하나요?

Flask의 g는 한 HTTP 요청 동안만 살아있는 저장소입니다. 여러 함수에서 get_db()를 호출해도 동일한 연결 객체를 재사용하여, 불필요한 DB 연결 생성을 막습니다.

실무 커넥션 풀 vs 요청 단위 연결

SQLite는 파일 기반이라 연결 비용이 낮아 요청 단위로 충분합니다. 하지만 PostgreSQL/MySQL을 사용하는 실무 환경에서는 커넥션 풀을 사용합니다 (예: SQLAlchemy의 create_engine(pool_size=10)). 풀은 미리 연결을 만들어두고 재사용하여, 연결 생성 오버헤드를 제거합니다.

5. Step 2 — CRUD 전체 구현

Step 2 입문

CRUD란?

Create(생성), Read(조회), Update(수정), Delete(삭제). 데이터를 다루는 4가지 기본 작업입니다. 거의 모든 웹 애플리케이션의 핵심입니다.

작업HTTP 메서드SQL비유
CreatePOSTINSERT새 글 쓰기
ReadGETSELECT글 읽기
UpdatePOSTUPDATE글 수정
DeletePOSTDELETE글 삭제
Step 2

HTTP 메서드와 URL 설계

입문 웹에서는 URL과 HTTP 메서드의 조합으로 "무엇을 할 것인가"를 결정합니다.

URLGET (읽기)POST (쓰기)
/posts글 목록 보기새 글 등록
/posts/new글쓰기 폼—
/posts/11번 글 상세1번 글 수정
/posts/1/edit1번 글 수정 폼—
/posts/1/delete—1번 글 삭제

중급 RESTful API 관점

이 프로젝트의 URL 설계는 REST 원칙을 부분적으로 따릅니다. 완전한 REST에서는 DELETE /posts/1처럼 HTTP DELETE 메서드를 사용하지만, HTML 폼은 GET/POST만 지원하므로 실무에서도 이 방식이 흔합니다. API 서버라면 method=DELETE를 사용하는 것이 정석입니다.

Step 2

주요 코드 해설

Create — 글 등록

@app.route("/posts", methods=["POST"])
def posts_create():
    title = request.form.get("title", "").strip()    # 폼 데이터 읽기
    content = request.form.get("content", "").strip()

    if not title or not content:                       # 유효성 검사
        return _validate_post_form(title, content, "create")

    db = get_db()
    cursor = db.execute(
        "INSERT INTO posts (title, content) VALUES (?, ?)",  # 파라미터화 쿼리
        (title, content),
    )
    db.commit()                                        # 트랜잭션 확정
    return redirect(url_for("posts_detail", post_id=cursor.lastrowid))

입문 cursor.lastrowid는 방금 INSERT된 행의 id를 반환합니다. 글을 쓰고 바로 상세 페이지로 이동할 때 사용합니다.

Read — 글 상세

@app.route("/posts/<int:post_id>")
def posts_detail(post_id):
    db = get_db()
    post = db.execute(
        "SELECT id, title, content, created_at FROM posts WHERE id = ?",
        (post_id,),
    ).fetchone()

    if post is None:
        abort(404)                                    # 없는 글이면 404 에러

    return render_template("posts/detail.html", post=post)

중급 <int:post_id>는 URL의 동적 세그먼트입니다. Flask가 자동으로 정수로 변환하여 함수 인자로 전달합니다.

이슈

Step 2 자주 발생하는 이슈

1) 글을 써도 저장이 안 됨

원인: db.commit() 누락. SQLite는 기본적으로 auto-commit이 아닙니다.

해결: INSERT/UPDATE/DELETE 후 반드시 db.commit()을 호출하세요.

2) 404 Not Found가 자꾸 뜸

원인: URL 오타 또는 fetchone() 결과가 None인데 처리하지 않음.

해결: if post is None: abort(404) 패턴을 모든 상세/수정/삭제 함수에 적용하세요.

3) 글 수정이 안 되고 새 글이 계속 생김

원인: 폼의 action URL이 수정용이 아닌 생성용으로 설정됨.

해결: 수정 모드에서는 form_action=url_for("posts_update", post_id=post_id)를 사용하세요.

Tailwind CSS란?

미리 만들어진 CSS 클래스를 조합하여 디자인하는 유틸리티 퍼스트 CSS 프레임워크입니다. CSS 파일을 직접 작성하지 않아도 됩니다.

중급 CDN vs 빌드 방식

이 프로젝트는 <script src="https://cdn.tailwindcss.com"> CDN 방식을 사용합니다. 빠른 프로토타이핑에 적합하지만, 실무에서는 PostCSS 빌드 방식을 사용하여 사용하지 않는 CSS를 제거(Tree-shaking)하고 파일 크기를 최적화합니다.

1) jinja2.TemplateNotFound

원인: 템플릿 파일 위치가 잘못됨. Flask는 templates/ 폴더에서만 찾습니다.

해결: 수정 라우트에서 DB에서 읽은 값을 템플릿에 넘겨야 합니다.

7. Step 4 — 페이지네이션 & 검색 & 정렬

Step 4 입문

페이지네이션 (Pagination)

게시글이 수백 개가 되면 한 화면에 다 보여줄 수 없습니다. 페이지네이션은 데이터를 정해진 개수만큼 나누어 보여주는 기법입니다.

PER_PAGE = 10                    # 한 페이지에 10개

total = db.execute(f"SELECT COUNT(*) FROM posts {where_clause}", params).fetchone()[0]
total_pages = max(1, (total + PER_PAGE - 1) // PER_PAGE)   # 올림 나눗셈
page = min(page, total_pages)                                # 범위 보정
offset = (page - 1) * PER_PAGE

posts = db.execute(
    f"SELECT ... {where_clause} {order_clause} LIMIT ? OFFSET ?",
    params + [PER_PAGE, offset],
).fetchall()

입문 LIMIT / OFFSET 이해하기

pageLIMITOFFSET가져오는 데이터

Step 4 입문

검색 (Search)

사용자가 입력한 키워드를 제목과 내용에서 찾습니다. SQL의 LIKE 연산자를 사용합니다.

search = request.args.get("q", "").strip()

if search:
    where_clause = "WHERE title LIKE ? OR content LIKE ?"
    params.extend([f"%{search}%", f"%{search}%"])

# URL: /posts?q=Flask → WHERE title LIKE '%Flask%' OR content LIKE '%Flask%'

중급 LIKE vs Full-Text Search

LIKE '%키워드%'는 간단하지만 데이터가 많아지면 느려집니다 (전체 스캔). 실무에서는 SQLite의 FTS5 (Full-Text Search)나 PostgreSQL의 tsvector를 사용합니다.

Step 4 입문

정렬 (Sort)

order_map = {
    "newest":     "ORDER BY created_at DESC",   # 최신순 (기본)
    "oldest":     "ORDER BY created_at ASC",    # 오래된순
    "title_asc":  "ORDER BY title ASC",         # A→Z
    "title_desc": "ORDER BY title DESC",        # Z→A
}
order_clause = order_map.get(sort, order_map["newest"])

중급 정렬 보안: 화이트리스트 패턴

사용자 입력을 직접 SQL에 넣으면 SQL Injection 위험이 있습니다. 이 코드는 order_map.get(sort, 기본값)으로 미리 정의된 값만 허용하는 화이트리스트 방식을 사용하여 안전합니다.

Step 4

조합: 검색 + 정렬 + 페이지네이션

세 기능 모두 URL 파라미터로 동작하므로 자연스럽게 조합됩니다.

URL: /posts?q=Python&sort=oldest&page=2

→ WHERE title LIKE '%Python%' OR content LIKE '%Python%'
→ ORDER BY created_at ASC
→ LIMIT 10 OFFSET 10

페이지 이동 시에도 q와 sort를 URL에 유지하여 검색/정렬 상태가 초기화되지 않습니다.

중급 WSGI란?

Web Server Gateway Interface. Python 웹 애플리케이션과 웹 서버 간의 표준 통신 규약입니다. Flask의 app.run()은 개발용이며 동시 접속을 처리하지 못합니다. Gunicorn은 여러 worker 프로세스를 띄워 다중 요청을 동시에 처리합니다.

Step 5 자주 발생하는 이슈

1) Application failed to respond

원인: Start Command가 잘못되었거나 포트 바인딩 문제.

해결: Start Command를 정확히 확인: gunicorn app:app --bind 0.0.0.0:$PORT

2) 배포 후 데이터가 자꾸 초기화됨

원인: Render는 기본적으로 ephemeral filesystem을 사용합니다. 재배포 시 파일이 사라집니다.

해결: Render 대시보드에서 Disk 추가 (Mount Path: /var/data) + 환경변수 DATABASE_PATH=/var/data/posts.db 설정.

3) Build failed: ModuleNotFoundError

원인: requirements.txt에 필요 패키지가 빠졌거나, 파일이 저장소에 커밋되지 않았습니다.

해결: pip freeze > requirements.txt 후 git add, git commit, git push.

중급 SQL Injection과 파라미터화 쿼리

사용자 입력을 문자열拼接으로 SQL에 넣으면 해킹 위험이 있습니다:

# 위험! SQL Injection 가능
db.execute(f"SELECT * FROM posts WHERE title = '{title}'")

# 안전: 파라미터화 쿼리 (? 사용)
db.execute("SELECT * FROM posts WHERE title = ?", (title,))

? 자리에 값이 안전하게 바인딩되어, 악의적인 SQL이 실행되지 않습니다. 이 프로젝트의 모든 쿼리는 파라미터화 방식을 사용합니다.
